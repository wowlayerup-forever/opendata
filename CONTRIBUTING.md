# Contributing

Thanks for helping. The bar is "a stranger, or an agent, can trust this row," which means provenance matters more than volume.

## Before you start

Everyone taking part in this project follows the [code of conduct](CODE_OF_CONDUCT.md). Report problems to [wowlayerup@gmail.com](mailto:wowlayerup@gmail.com).

Read [CONVENTIONS.md](CONVENTIONS.md). It is short. The validator enforces most of it, but the parts it cannot enforce (which layer a fact belongs in, whether a count is honest) are on you. The working rules, setup and test commands are in [AGENTS.md](AGENTS.md); they apply to people and coding agents alike.

**Just want to contribute what you see in game?** You do not need any of this: install the collector addon and the uploader from the releases, as described in the [README](README.md#contribute-observations-players).

## How data gets in

1. **Client data** (`data/client/`, `data/api/`) is generated by the extractor from a Forever client build. Do not hand-edit these files. If something is wrong, it is wrong in the extractor; open an issue with the build string and the row.
2. **World observations** (`data/world/`) arrive as pull requests from the nightly reconcile workflow, which aggregates every player's uploaded batches with `tools/reconcile.py` (`source.kind: observation`, with sample sizes). Do not edit observation rows by hand; they are regenerated every night. You can also add rows by hand with `source.kind: manual` and `confidence: unverified`. Say in the PR how you know.
3. **Market aggregates** (`data/market/`) come from the reconciler only.
4. **Derived content** (`data/derived/`) is open to anyone. Fill in `author`, `generator`, `dataset_version` and `criteria`. If an agent wrote it, say which model.

## Pull request checklist

- `python tools/validate.py` passes locally.
- New rows reference only IDs that exist in `data/client/`. (References to quests and NPCs nobody has seen yet are warnings, not errors: those tables are filled from players' client caches and are partial.)
- No bare percentages. Drops and kills, not rates.
- No opinion in a fact table.
- Files stay sorted by primary key and one record per line.
- The PR description says where the data came from.

## Reporting a wrong row

Open an issue with the dataset version, the table, the primary key, what you observed instead, and roughly how many times. If an observation contradicts a `verified` row, the reconciler marks the row `disputed` rather than overwriting it, so that consumers can see the conflict.

## Code

`tools/` is Python 3.11+, standard library plus `jsonschema`. Keep it that way; the point is that anyone can run it. Formatting with `ruff format` is appreciated but not enforced yet. [AGENTS.md](AGENTS.md) lists which tests to run for which change; CI runs them all on every pull request, and `main` only accepts pull requests with green checks.
